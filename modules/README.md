# 模块

可选能力包。**默认不用装**——画像仓在本地，模块就在里面，主 `SKILL.md` 按需读对应目录。

## 什么时候用模块

核心那几份只回答「这个人是谁」。具体到「怎么切 GitHub 账号」「怎么读本机微信」这类有工具依赖、平台依赖、安全前提的能力，塞进核心只会让不用它的人背一堆噪音。

## 三种用法，按需要挑

### 默认：什么都不用做

主 `SKILL.md` 会按场景读 `modules/<模块名>/SKILL.md`。用户说「看看我现在 GitHub 是哪个账号」，就读 `modules/github-accounts/SKILL.md`。零安装。

### 可选：让它单独出现在 magpie 里

如果你希望它在技能列表里独立出现、能被自己的 description 触发，就在 magpie 里把仓库的这个子目录加成独立技能。magpie 的 git 源认仓库内的路径（文档里支持 GitLab/Gitea 的 `/-/tree/<ref>/<path>` 形式）。

**这条没在你的 magpie 上实测过**，具体填法以当前版本为准。填不进去就用默认方式，功能不受影响。

### 不建议：手工复制进技能目录

magpie「只清理自己写过的内容」，你手工放进去的会被当成你自己的技能留着。结果是两套来源并存，改哪份都说不清。

## 规划中

按需再写，不预留空壳：

- `mail` —— 邮箱只读检索与账号路由
- `servers` —— 服务器 Profile、主机指纹核对、连接诊断
- `wechat-readonly` —— 本机微信记录只读查询（平台相关，Windows 优先；可参考 personal-agent-foundation 的 `wechat-readonly-analyst`）

## 写模块的约定

- 一个模块一个目录，`SKILL.md` 在根
- 模块只读核心画像，不改核心画像
- 模块不得把凭据写进任何文件
- 模块自己声明依赖；依赖缺失时明确报「没装什么」，不要静默降级
