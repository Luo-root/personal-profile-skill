# 内容发布

**状态：骨架，未实现。** 这里定义的是流程与闸门，不是能直接用的发布工具。

**平台不枚举。** 下面按「有没有官方接口」分类：今天可以是公众号和知乎，明天加 CSDN 或 B 站，判断方法不变。

## 铁律

- **人负责审稿、审片，并决定发不发。** 默认只做到「待审稿」为止：Agent 准备，本人看，本人拍板。
- 用户说「可以发了」是**单次**授权，不延续到下一条内容。
- 不把 cookie、AppSecret、access_token 写进任何文件。
- 发之前要回读平台侧的真实状态（草稿建成没有、视频过审没有），不能只凭脚本返回码。

## 先判平台属于哪一类

新增平台时，先查它有没有官方发布接口，别假设：

| 类别 | 典型 | 能做到哪一步 |
| --- | --- | --- |
| 有官方接口 | 微信公众号（草稿箱 + 发布，需 AppID/AppSecret 与 IP 白名单）、部分技术社区 | 真自动化：建草稿 → 人审 → 发布 |
| 只有浏览器操作 | 小红书、抖音、多数内容社区 | 只能出方案 + 素材；自动发靠浏览器操作，有风控与稳定性风险 |
| 只能人工 | 一些封闭平台 | 只输出待发内容与人工作业清单 |

判断依据以平台当期文档为准，不凭印象。**查不到就当「只能人工」，不要假装能自动发。**

## 流程

1. 读 `profile/my-setup.md` 的「社交媒体」，拿到平台、账号、**权限档位**
2. 按档位决定停在哪一步：
   - 只能出方案 → 标题、正文、标签、封面建议
   - 能建草稿 → 建草稿，把草稿位置回给本人
   - 可自己发 → 仍然先发预览给本人确认
3. 发布后回读平台状态，把真实结果报回去

## 个人微信不在此列

个人微信属于通信渠道，不走内容审核流程：读记录、发消息按 `profile/my-setup.md` 的「微信」一节执行，不额外设限。
